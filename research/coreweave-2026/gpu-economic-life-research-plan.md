# 후속편 연구 설계 — GPU는 3년짜리 자산인가, 6년짜리 현금흐름인가?

기준일 2026-11-12. 이 문서는 설계이며 실증 결과나 후속편 원고가 아니다. 1편의 투자 결론을 확인하는 방향으로 결과를 유도하지 않는다.

## 1. 질문과 반증 조건

1. 기술적 수명: 특정 모델과 워크로드가 하드웨어·메모리·소프트웨어 조건에서 실행 가능한 기간.
2. 경제적 수명: 남은 운용 현금흐름의 현재가치가 계속 보유할 때의 기회비용 및 필요한 향후 투자보다 높은 기간. 매몰된 취득원가는 계속 운용 의사결정에서 제외하되 초기 투자 IRR에서는 포함한다. 발전기·네트워크·시설의 대체 사용가치와 자본비용을 명시한다.
3. 회계적 수명: 감가상각 배분 추정 기간. [CoreWeave 2025 10-K, 회계정책](https://www.sec.gov/Archives/edgar/data/1769628/000176962826000104/crwv-20251231.htm)은 2023년 컴퓨팅 장비를 5년에서 6년으로 변경했다고 설명한다. 물리 수명과 현금창출 기간의 증명이 아니다.

가설 A: 차세대 장비의 처리량·에너지 효율이 개선돼 구형 장비의 성능당 가격과 재계약 단가가 하락한다. 가설 B: 중소형 모델과 에이전트 등 여러 수요가 장비의 판매 가능 시간을 연장한다. 두 효과가 공존할 수 있다. 단가·활용률·재계약 가능성의 관측 자료가 없으면 수명을 추정하지 않는다.

## 2. 자료 설계

| 파일/관측 단위 | 필수 필드 | 출처 및 제약 |
| --- | --- | --- |
| GPU 사양 / 모델 × 모델명 | 발표일, 실제 출하/클라우드 제공일, VRAM, 대역폭, TDP, 인터커넥트, 서버 구성, 출처 | NVIDIA 제품 자료; 발표와 실제 배포 분리 |
| 가격 / 플랫폼 × SKU × 지역 × 날짜 × 약정 | 전체 시스템 시간당 가격, GPU 수, CPU·RAM·스토리지·네트워크 포함 여부, 예약/스팟/온디맨드, 세금, 재고 | [Google Cloud GPU 가격](https://cloud.google.com/products/compute/pricing/accelerator-optimized), 사업자별 공식 가격표; 공개 정가 ≠ 실제 계약 단가 |
| 처리량 / 서버 구성 × 모델 × 시험 | 가속기 수, 모델과 버전, 입력·출력 길이 분포, 정밀도, 배치·동시성, p50/p95 TTFT·ITL, 완료 토큰/초, 오류율 | [MLPerf 공개 결과](https://mlcommons.org/benchmarks/inference-datacenter/), [NVIDIA AIPerf](https://docs.nvidia.com/aiperf/getting-started/ai-perf-comprehensive-llm-benchmarking); 워크로드·SLA 일치하지 않으면 직접 비교 금지 |
| 태스크 / 모델 × 데이터셋 × 결과 | 프롬프트와 버전, 정답·검증 규칙, 성공률, 재시도·escalation, 평가 비용 | 공개 평가셋 또는 재현 가능한 사용자 동의 데이터; 유출 방지 |
| 코호트 / 투입 연도 × GPU × 계약 유형 | 초기 투자, 서비스 개시, 가용 시간, 사용률, 가격, 전력·시설·운영, 재계약, 잔존가치, 차입 | 공시되지 않으면 범위 가정; 실제 회사 코호트라고 표시하지 않음 |

시간 패널은 관측일과 요금 유효일을 별도로 기록한다. 보존된 요금표가 없으면 역사적 가격을 채우지 않는다. 중고 거래는 체결 여부, 재고·상태·부가세·지역을 기록하며 호가와 체결가를 구분한다. 고객 수요가 공급 부족기인지 과잉기인지 같이 표시한다.

## 3. 비교 실험

- 공개 모델 2~3개와 쉬운 구현·복잡한 코딩·정형 분류 과제를 선택한다. 동일 정답검증과 토큰 조건을 고정하고 작은 모델이 과제 요구 성능을 충족하지 못하면 저렴하다는 이유로 동등하다고 취급하지 않는다.
- GPU 세대와 서버 구성에서 고정 지연 SLO를 만족하는 최대 처리량과 실효 가동률을 측정한다. 프리필·디코드를 분리하며 각 모델의 정밀도, 배치와 메모리 사용을 기록한다. GPU 시간을 GPU 대수로 중복 곱하지 않는다.
- 토큰 100만 개당 총비용 = 일정 시간의 전체 시스템 비용 / 같은 시간에 완료한 유효 토큰 수 × 100만. 입력·출력 토큰 구성이 다른 API와 직접 비교할 때는 별도 가격표 및 캐시/추론 토큰 정책을 기록한다.
- 성공 건당 비용 = 모든 시도·재시도·라우팅·에스컬레이션 비용 / 검증된 성공 건수. 요청량이 늘어도 구형 GPU에 배정되는 점유율과 가격이 유지된다는 가정을 두지 않는다.
- 반복 실험과 부트스트랩 구간, 낮은 동시성과 포화 직전의 민감도를 함께 제시한다. 벤치마크 수치와 실제 임대계약 가격은 구분한다.

## 4. 코호트 모형

연도별 매출 = 가용 GPU 시간 × 유료 가동률 × 실현 시간당 임대료. 여기에 전력·네트워크·운영·유지·시설 임대와 장애를 반영한다. 초기에는 GPU 외 서버·인터커넥트·설치·시설 지분을 포함하고, 계약 만료 시 재계약 확률·가격·유휴 시간·재배치비와 회수 가능 중고가격을 모델링한다.

무차입 NPV는 세후 영업현금흐름에서 미래 투자비를 뺀 값을 자본비용으로 할인한다. 주주 IRR은 실제 차입·원리금·증자와 분배 시점을 반영한다. GPU 원가 회수, 전체 프로젝트 회수, 주주 IRR을 혼용하지 않는다. 금융리스 부채를 차감하는 경우 리스 지급도 같은 현금흐름에서 다시 차감하지 않는다.

민감도: 단가, 실제 유료 가동률, 전력·시설 비용, 초기 장비 가격, 신세대 장비의 토큰당 비용, 재계약 확률·가격, 유휴기간, 자본비용과 잔존가치를 개별·동시 변동한다. 계약 중인 GPU와 만료 이후 재계약을 분리한다. 세대교체와 전력 제약이 함께 발생할 수 있으므로 독립확률로 합산하지 않는다.

## 5. 실행 순서와 한계

1. GPU별 공식 기술 사양과 실제 클라우드 공급 개시일을 수집한다.
2. 구형 및 신형 가격표의 동일 시점·동일 지역·동일 약정 비교 가능 표본을 만든다.
3. MLPerf와 공개 벤치마크의 동일 모델·SLO를 선별하고, 불일치를 기록한다.
4. 실험 환경과 예산이 확보될 때 직접 동일 태스크 실험을 한다. 아직 측정하지 않은 수치로 차트를 만들지 않는다.
5. 코호트 NPV·IRR과 1편의 역산 입력값을 연결한다. 공시 부족으로 특정 코호트의 실제 가격과 수익률을 식별할 수 없다면 범위를 유지하고 결론을 유보한다.
